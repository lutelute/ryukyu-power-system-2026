まず直感で（3 分でつかむ）

📌 一言でいうと：再エネの出力予測は「気象を予測し、物理式で MW に翻訳する」2 段階。誤差は両方から来て、風力では 3 乗で増える。

🪄 たとえ話：天気予報を「通訳」する

通訳 再エネ予測
脚本（明日の空）を 別の言葉に訳す 数値予報 → 変換モデル → MW
誤訳の原因は 脚本の誤り と 通訳の癖 予報誤差 と モデル誤差（温度・汚れ）
ビルの屋上ほど 風が強い べき法則でハブ高さへ補正
通訳は 1 対 1 で訳す 風力は v³。小さな誤りが 3 倍に
大勢に聞けば 平均は当たりやすい 平滑化効果：多地点集約で誤差が減る

崩れる点：通訳は言葉を 1 対 1 で置き換えるが、風力は 3 乗則で誤差を増幅する。だから風力予測は太陽光より難しい。

📰 事例：2018年10月 九州で日本初の再エネ出力制御 晴天で需要の軽い休日、太陽光の出力が需要に迫り、揚水と連系線を使い切っても 余った。太陽光に一時停止を指示する出力制御が国内で初めて実施された。予測が当たったからこそ、前日に指示が出せた。

📰 事例：台風と雲 — 沖縄の 2 つの急変 台風では風車がカットアウト風速（約 25 m/s）で一斉に停止し、出力が数分でゼロになる。日射の強い沖縄では雲の通過で太陽光が数分で数割変わる。どちらも「いつ」を当てる予測が要る。

🤔 この回の式で読むと：予測は「当てる」ためだけでなく「備える量を決める」ためにある。第8回の予備力につながる。

🤔 なぜ MAPE を使わないのか 太陽光は夜間の実績が 0 で、百分率誤差が発散する。定格で割った nRMSE なら常に意味を持ち、規模の違う設備も比較できる。

🤔 なぜ集めると誤差が減るのか 地点ごとの誤差が独立なら、N 地点の合計の誤差は 1/√N に縮む。実際は雲や前線で誤差が相関するので、σ₁√ρ という下限が残る。

⚠ 風力は v³ 風速 10% の誤りが出力 33% の誤りになる。高さ補正と地形補正を省略しない。

この回の地図：Ⅰ 数値気象予報（NWP）の枠組みと予測の流れ → Ⅱ 日射 → 太陽光出力（温度で目減りする） → Ⅲ 風速 → 風力出力（べき法則とパワーカーブ） → Ⅳ 誤差の評価、平滑化効果、アンサンブル、出力制御

10.1 導入

学習目標

  1. 数値気象予報（NWP）の枠組み（支配方程式・格子・データ同化）を説明できる。
  2. 日本で利用可能な気象モデル（GSM/MSM/LFM）と気象データの入手方法を説明できる。
  3. 日射量から太陽光発電量を推定するモデルを構築できる。
  4. 風速から風力発電量を推定でき、ハブ高さ補正ができる。
  5. 気象予測の不確実性を定量化し、アンサンブル予報の意義を説明できる。
  6. 沖縄の気象特性が再エネ予測にもたらす固有の課題を論じられる。

10.2 理論

10.2.1 数値気象予報（NWP）の枠組み

大気の運動は物理法則で記述できる。これを数値的に解くのが NWP である。

支配方程式（プリミティブ方程式系）:

式 内容
運動方程式（ナビエ・ストークス） 風の運動。コリオリ力・気圧傾度力・摩擦
連続の式 質量保存
熱力学の式 エネルギー保存
状態方程式 p=ρRTp = \rho R Tp=ρRT
水蒸気の保存式 水循環・雲・降水

これらを3 次元格子上で離散化し、時間積分する。

予報の 3 要素:

  1. モデル — 方程式系と離散化、物理過程のパラメタリゼーション
  2. 初期値 — 観測データから作る現在の大気状態
  3. 境界条件 — 領域モデルの場合、外側からの流入

データ同化: 観測（地上・ラジオゾンデ・航空機・衛星・レーダー）と 前回の予報値を統計的に融合し、最良の初期値を作る。 4 次元変分法（4D-Var）やアンサンブルカルマンフィルタが使われる。

ここが重要 — カオス性: 大気は初期値鋭敏性を持つ非線形系（ローレンツの発見）。 初期値のわずかな誤差が指数関数的に増大する。 このため決定論的予報には原理的な限界があり、 実用的な予報可能期間は 1〜2 週間程度とされる。

図 10.1　再エネ出力予測の 2 段構え。数値予報で空を予測し、地点・ハブ高さへ補正し、物理モデルで MW に翻訳して、nRMSE で評価する。誤差は「空の予測」と「翻訳の式」の両方から来る。

10.2.6 予測誤差の評価と正規化

第11回で詳しく扱うが、ここで再エネ予測固有の注意点を述べる。

MAPE を使ってはいけない場面:

MAPE=100T∑t∣yt−y^tyt∣\text{MAPE} = \frac{100}{T}\sum_t\left|\frac{y_t-\hat{y}_t}{y_t}\right|MAPE=T100​t∑​​yt​yt​−y^​t​​​

太陽光は夜間 yt=0y_t = 0yt​=0 になるため MAPE が発散する。 昼夜を通した評価には使えない。

再エネ予測の標準的な指標は、定格容量で正規化した誤差である。

nRMSE=1Prated1T∑t=1T(yt−y^t)2×100 [%]\boxed{\text{nRMSE} = \frac{1}{P_\text{rated}}\sqrt{\frac{1}{T}\sum_{t=1}^{T}(y_t-\hat{y}_t)^2}\times100\ [\%]}nRMSE=Prated​1​T1​t=1∑T​(yt​−y^​t​)2​×100 [%]​

実用上の目安（翌日予測、単一サイト）:

電源 nRMSE の目安
太陽光（単一サイト） 8〜15%
太陽光（広域集約） 4〜8%
風力（単一サイト） 12〜20%
風力（広域集約） 8〜12%

平滑化効果（smoothing effect）: 多数のサイトを集約すると、 個々の誤差が打ち消し合って相対誤差が小さくなる。 サイトが独立なら誤差は 1/N1/\sqrt{N}1/N​ で減るが、 実際には気象の空間相関があるため、そこまでは下がらない。

沖縄の不利な点: 系統が小さく、地理的な広がりも限られるため、 平滑化効果が本土より働きにくい。同じ島の中では雲の動きが相関するからである。

図 10.7　予測誤差の評価。MAE 0.058 MW、RMSE 0.093 MW、定格で正規化した nRMSE は 4.6%。夜間は実績がほぼ 0 になるため MAPE が発散し（右図）、太陽光の評価には使えない。

図 10.8　平滑化効果。誤差が独立なら地点数 N に対して 1/√N で減るが（9 地点で 15% → 5.0%）、地点間に相関 ρ があると σ₁√ρ が下限として残る。同じ雲・同じ前線が効く狭い地域では平滑化に期待できない。

10.2.7 アンサンブル予報と確率予測

カオス性（10.2.1 節）のため、単一の決定論的予報には限界がある。 そこで初期値やモデル物理をわずかに変えた複数のシミュレーションを走らせる。

アンサンブル予報の使い方:

使い方 内容
アンサンブル平均 メンバーの平均。単独予報より精度が良いことが多い
スプレッド メンバーのばらつき。予測の不確実性の指標
確率予測 「発電量が X MW を下回る確率 20%」のような表現
分位点予測 10%、50%、90% 分位点を出す

なぜ確率予測が電力で重要か: 第8回で見たとおり、 需給計画では予備力をどれだけ持つかを決める必要がある。

必要予備力=f(予測誤差の分布)\text{必要予備力} = f(\text{予測誤差の分布})必要予備力=f(予測誤差の分布)

点予測（1 つの数値）だけでは予備力を決められない。 「どれくらい外れうるか」の情報が要る。 スプレッドが大きい日は予備力を厚くし、小さい日は薄くする、という運用ができる。

図 10.9　アンサンブル予報。初期値をわずかに変えた 21 メンバーの予報は先になるほど広がり、24 時間先で ±0.5 m/s、48 時間先で ±0.9 m/s になる。この広がり（スプレッド）が予測の不確実性を表す。

台風の常襲 風車のカットアウト（25 m/s 超）が頻発。出力が定格→0 に急変
亜熱帯・高温 太陽光の温度損失が大きい（10.2.4 節で 16% 試算）
海洋性気候・積雲 積雲の発達・移動が速く、日射量の短時間変動が大きい
島嶼で地理的広がりが小 平滑化効果が働きにくい
梅雨・秋雨 長期間の低日射
塩害 設備劣化（予測ではなく保守の問題）

特に重要なのは日射の短時間変動（ランピング）である。 積雲が太陽を横切ると、数十秒で出力が 50% 以上変動することがある。 これは NWP（格子 2〜5 km、更新 1〜3 時間）では原理的に捉えられない。

対策:

  • 全天カメラによる雲の移動追跡（数分先の予測）
  • 衛星画像からの雲移動ベクトル（数十分先）
  • 蓄電池による平滑化（第9回の FFR と同じ発想）

10.3.1 太陽光発電量モデルの実装

"""第10回 デモ1: 日射量・気温から太陽光発電量を推定する"""
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

plt.rcParams['font.family'] = ['Hiragino Sans', 'Yu Gothic', 'DejaVu Sans']

# ---------- 太陽位置（簡易 NOAA アルゴリズム） ----------
def solar_position(doy, hour, lat_deg, lon_deg, tz=9.0):
    """戻り値: 天頂角[deg], 方位角[deg]"""
    lat = np.deg2rad(lat_deg)
    decl = np.deg2rad(23.45)*np.sin(2*np.pi*(284+doy)/365)     # 赤緯
    B = 2*np.pi*(doy-81)/364
    EoT = 9.87*np.sin(2*B) - 7.53*np.cos(B) - 1.5*np.sin(B)    # 均時差[min]
    solar_time = hour + (4*(lon_deg - 15*tz) + EoT)/60
    omega = np.deg2rad(15*(solar_time - 12))                    # 時角
    cos_z = (np.sin(lat)*np.sin(decl)
             + np.cos(lat)*np.cos(decl)*np.cos(omega))
    cos_z = np.clip(cos_z, -1, 1)
    return np.rad2deg(np.arccos(cos_z)), np.rad2deg(omega)

# ---------- 発電量モデル ----------
def pv_power(G_poa, T_air, P_rated=1000.0,
             gamma=-0.004, noct=45.0, eta_sys=0.82):
    """PVWatts 型モデル。G_poa[W/m2], T_air[degC] -> 出力[kW]"""
    T_cell = T_air + (noct - 20)/800*G_poa
    P = P_rated*(G_poa/1000)*(1 + gamma*(T_cell - 25))*eta_sys
    return np.maximum(P, 0.0), T_cell

# ---------- 那覇の晴天日をシミュレート ----------
LAT, LON = 26.21, 127.68        # 那覇
doy = 196                        # 7月15日

# 晴天時の全天日射（簡易 Haurwitz モデル）
cos_z = np.cos(np.deg2rad(zenith))
G_clear = np.where(cos_z > 0, 1098*cos_z*np.exp(-0.059/np.maximum(cos_z, 1e-6)), 0)

# 気温の日変化（那覇の7月：最低27度、最高32度）
T_air = 29.5 - 2.5*np.cos(2*np.pi*(hours-14)/24)

P_naha, T_cell = pv_power(G_clear, T_air)
# 比較: 福井（気温が低い）
T_fukui = 26.0 - 4.0*np.cos(2*np.pi*(hours-14)/24)
P_fukui, T_cell_f = pv_power(G_clear, T_fukui)

fig, axes = plt.subplots(3, 1, figsize=(9, 9), sharex=True)
axes[0].plot(hours, G_clear, color="#f4a261", lw=2)
axes[0].set_ylabel("日射量 [W/m²]"); axes[0].set_title("那覇 7/15 晴天日のシミュレーション")
axes[0].grid(alpha=0.3)

axes[1].plot(hours, T_air, label="外気温（那覇）")

10.3.2 風力発電のパワーカーブと予測誤差の感度

"""第10回 デモ2: パワーカーブと風速誤差の伝播"""
import numpy as np
import matplotlib.pyplot as plt

plt.rcParams['font.family'] = ['Hiragino Sans', 'Yu Gothic', 'DejaVu Sans']

P_RATED, U_IN, U_RATED, U_OUT = 3.0, 3.0, 12.0, 25.0

def power_curve(u):
    u = np.asarray(u, dtype=float)
    P = np.zeros_like(u)
    mid = (u >= U_IN) & (u < U_RATED)
    P[mid] = P_RATED*((u[mid]**3 - U_IN**3)/(U_RATED**3 - U_IN**3))
    P[(u >= U_RATED) & (u <= U_OUT)] = P_RATED
    return P

def wind_shear(u10, z=90.0, z_ref=10.0, alpha=0.14):
    return u10*(z/z_ref)**alpha

u = np.linspace(0, 30, 600)
P = power_curve(u)
dPdu = np.gradient(P, u)

fig, axes = plt.subplots(1, 2, figsize=(13, 4.8))
axes[0].plot(u, P, lw=2.5, color="#264653")
for x, lab in [(U_IN, "カットイン"), (U_RATED, "定格"), (U_OUT, "カットアウト")]:
    axes[0].axvline(x, color="gray", ls=":", alpha=0.8)
    axes[0].text(x, 3.15, lab, ha="center", fontsize=8)
axes[0].set_xlabel("ハブ高さ風速 [m/s]"); axes[0].set_ylabel("出力 [MW]")
axes[0].set_title("パワーカーブ"); axes[0].grid(alpha=0.3); axes[0].set_ylim(0, 3.4)

axes[1].plot(u, np.abs(dPdu)*1000, lw=2, color="#e63946")
axes[1].set_xlabel("風速 [m/s]"); axes[1].set_ylabel("$|dP/du|$ [kW / (m/s)]")
axes[1].set_title("風速誤差 1 m/s あたりの出力誤差")
axes[1].grid(alpha=0.3)
peak = u[np.argmax(np.abs(dPdu))]
axes[1].axvline(peak, color="k", ls="--", alpha=0.7)
axes[1].text(peak+0.4, np.max(np.abs(dPdu))*900, f"最大 {peak:.1f} m/s", fontsize=9)
plt.tight_layout()
plt.savefig("../図/ch10_power_curve.png", dpi=150)

print("=== ハブ高さ補正の効果 ===")
for u10 in [4, 6, 8, 10]:
    u_hub = wind_shear(u10)
    print(f"地上10m {u10:2d} m/s → ハブ90m {u_hub:5.2f} m/s | "
          f"出力 {power_curve(u10):.3f} → {power_curve(u_hub):.3f} MW")

print("\n=== 風速予測誤差 ±1 m/s の出力誤差 ===")
for u0 in [5, 8, 11, 14, 24.5]:
    e = (power_curve(u0+1) - power_curve(u0-1))/2
    print(f"風速 {u0:4.1f} m/s: 出力誤差 ±{abs(e)*1000:6.1f} kW "

10.3.4 平滑化効果の検証

"""第10回 デモ4: サイト集約による予測誤差の低減"""
import numpy as np
import matplotlib.pyplot as plt

plt.rcParams['font.family'] = ['Hiragino Sans', 'Yu Gothic', 'DejaVu Sans']
rng = np.random.default_rng(0)

def aggregate_nrmse(n_sites, corr, sigma=0.12, n_trial=4000):
    """空間相関 corr を持つ n_sites の平均誤差の標準偏差"""
    # 等相関モデル: 共通成分 + 独立成分
    common = rng.normal(0, np.sqrt(corr), (n_trial, 1))
    indep  = rng.normal(0, np.sqrt(1-corr), (n_trial, n_sites))
    err = sigma*(common + indep)          # 各サイトの誤差
    return err.mean(axis=1).std()

n_range = np.arange(1, 101)
fig, ax = plt.subplots(figsize=(8.5, 5))
for corr, label, color in [(0.0, "相関なし（理想）", "#2a9d8f"),
                            (0.3, "相関 0.3（広域・本土）", "#e9c46a"),
                            (0.7, "相関 0.7（島嶼・沖縄）", "#e63946")]:
    vals = [aggregate_nrmse(n, corr)*100 for n in n_range]
    ax.plot(n_range, vals, lw=2, color=color, label=label)

ax.plot(n_range, 12/np.sqrt(n_range), "k:", label="$1/\\sqrt{N}$ 則")
ax.set_xlabel("集約するサイト数 $N$"); ax.set_ylabel("nRMSE [%]")
ax.set_title("平滑化効果 — 空間相関があると誤差は下がりにくい")
ax.legend(); ax.grid(alpha=0.3)
plt.tight_layout()
plt.savefig("../図/ch10_smoothing.png", dpi=150)

print(f"{'サイト数':>8} {'相関0.0':>10} {'相関0.3':>10} {'相関0.7':>10}")
for n in [1, 5, 10, 50, 100]:
    row = [aggregate_nrmse(n, c)*100 for c in (0.0, 0.3, 0.7)]
    print(f"{n:8d} {row[0]:10.2f} {row[1]:10.2f} {row[2]:10.2f}")

期待される結論: 相関 0 なら 1/N1/\sqrt{N}1/N​ で減るが、 相関 0.7（島嶼部を想定）ではサイトをいくら増やしても σcorr\sigma\sqrt{\text{corr}}σcorr​ より下がらない。 沖縄で平滑化効果が期待しにくい理由が定量的に示される。

(a) Open-Meteo API で那覇の 1 週間の気象予報を取得せよ。 (b) 10.3.1 節のモデルで発電量を推定し、日別の発電電力量 [MWh] を求めよ。 (c) 設備利用率を計算し、日本の太陽光の平均（約 14%）と比較せよ。 (d) 気温を一律 5 °C 下げた仮想ケースを計算し、温度の影響を定量化せよ。 (e) セル温度を下げる技術的手段を 2 つ挙げ、それぞれの費用対効果を論じよ。

問 10-6 沖縄本島北部に風力発電所（3 MW × 10 基、ハブ高さ 80 m）を計画する。

(a) 地上 10 m の風速が 6.5 m/s、海岸部（α=0.14\alpha=0.14α=0.14）のとき、 ハブ高さ風速と 1 基あたりの出力を求めよ（10.3.2 節のパワーカーブを使う）。 (b) 台風接近により風速が 30 m/s に達した。発電所の出力はいくらか。 (c) 風速予測が 24 m/s だったが実際は 26 m/s だった場合の予測誤差 [MW] を求めよ。 この誤差が系統運用に与える影響を、第8回の ΔP=KΔF\Delta P = K\Delta FΔP=KΔF を用いて論じよ。 （沖縄本島系統の K=150K = 150K=150 MW/Hz とする） (d) このようなカットアウト付近のリスクに対する運用上の対策を 2 つ提案せよ。

問 10-7 予測の不確実性と予備力について検討する。

(a) 太陽光 300 MW、風力 100 MW が接続された系統がある。 太陽光の nRMSE 10%、風力の nRMSE 15%、両者の誤差が独立とするとき、 合計の予測誤差の標準偏差 [MW] を求めよ。 (b) 誤差が相関係数 0.4 で相関している場合はどうなるか。 (c) 2σ2\sigma2σ の予備力を確保する場合の必要量を (a)(b) それぞれで求めよ。 (d) アンサンブル予報を用いると、日ごとに予備力を変えられる。 このメリットを定量的に論じよ（スプレッドが大きい日と小さい日の例を作ってよい）。

10.6 まとめ

キーポイント

  • 再エネの導入により、需給バランスの不確実性が供給側にも入った。 第8回の ΔP=KΔF\Delta P = K\Delta FΔP=KΔF の ΔP\Delta PΔP を決めるのが気象予測である。
  • NWP は物理方程式を格子上で解く。3 要素はモデル・初期値・境界条件。 大気のカオス性により予報可能期間には原理的限界がある（1〜2 週間）。
  • 日本では GSM（20 km、週間）、MSM（5 km、翌日の主力）、 LFM（2 km、当日）、MEPS（アンサンブル）が使える。
  • 太陽光: P=PratedGPOA1000[1+γ(Tcell−25)]ηsysP = P_\text{rated}\dfrac{G_\text{POA}}{1000}[1+\gamma(T_\text{cell}-25)]\eta_\text{sys}P=Prated​1000GPOA​​[1+γ(Tcell​−25)]ηsys​。 温度係数が負なので高温の沖縄では出力が伸びにくい（試算で 16% 損失）。
  • 風力: 気象データの地上 10 m 風速をべき法則でハブ高さに補正すること。 忘れると 50% 以上の過小評価になる。 予測誤差が最大なのはパワーカーブの傾きが最大の領域とカットアウト付近。
  • 評価指標: 太陽光は夜間 y=0y=0y=0 で MAPE が発散するため、 定格容量で正規化した nRMSE を使う。
  • 平滑化効果: サイト集約で誤差は減るが、空間相関があると 1/N1/\sqrt N1/N​ ほどには減らない。 島嶼部の沖縄では平滑化が効きにくい。
  • アンサンブル予報により不確実性（スプレッド）を定量化でき、 予備力を日ごとに最適化できる。予測精度の改善は直接コスト削減になる。

次回への橋渡し

第10回では供給側（再エネ発電量）の予測を扱った。 第11回では需要側の予測を扱う。

需要予測は再エネ予測より歴史が古く、統計的手法が確立されている。 季節性・週日性・時間帯別のパターン、気温との非線形な関係（冷暖房需要）を 回帰分析と ARIMA モデルで扱う。

第12回では、両者を機械学習で統一的に扱う。
