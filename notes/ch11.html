まず直感で（3 分でつかむ）

📌 一言でいうと：電力需要はトレンド・年周期・週周期・日内変動・気温効果に分解できる。素朴な「前週同曜日」に勝って初めて価値がある。

🪄 たとえ話：需要は体温調節

体 電力需要
暑ければ汗、寒ければ震え 冷房・暖房の V 字 の気温応答
快適な温度から 離れるほど 反応が強い 度日（CDD/HDD）＝快適からの距離
平日と休日で 生活のリズム が違う 曜日効果（平日・土日・祝日）
朝起きて夜寝る 体内時計 日内変動（朝夕のピーク）
昨日の暑さが今日に残る 蓄熱（前日気温のラグ）

崩れる点：体は「慣れる」が、慣れは線形ではない。前日・前々日の気温をラグで入れる理由。

📰 事例：2022年3月22日 東京エリアの需給ひっ迫警報 地震で火力が止まっていたところに、季節外れの寒さと曇天が重なった。暖房需要が増え、太陽光が出ず、需要が 予測を上回った。国は初めて「需給ひっ迫警報」を出し、節電を呼びかけた。

📰 事例：2022年6月末 猛暑の需給ひっ迫注意報 梅雨明けが早く、記録的な暑さで冷房需要が急増した。過去の同じ時期のデータに頼れない状況だった。沖縄は冷房需要の割合が高く、気温 1 °C の差が需要に直結する。

🤔 この回の式で読むと：どちらも気温効果が主役。今日の重回帰の気温項がそのまま効く。

🤔 なぜ電力では RMSE を重く見るのか 予備力は最悪の外れに備えて持つ。平均的な外れ（MAE）より、大外れを強く罰する RMSE の方が運用の痛みに近い。

🤔 なぜ前週同曜日と比べるのか 曜日・季節・時刻をほぼ含む、最も手強い「何もしない予測」だから。これに勝てないモデルには価値がない。

⚠ 記録更新の日は苦手 学習範囲の外は、統計モデルも機械学習も外挿になる（第12回）。

この回の地図：Ⅰ 需要の分解 — トレンド・年・週・日 → Ⅱ 気温との非線形関係 — 度日と不快指数 → Ⅲ 重回帰モデル — 係数の読み方 → Ⅳ 評価 — 指標の使い分け、時系列分割、予備力へ

11.1 導入

学習目標

  1. 電力需要の3 つの周期性（年・週・日）を分解して説明できる。
  2. 需要と気温の非線形な関係をモデル化できる。
  3. 重回帰モデルで需要予測モデルを構築し、係数を解釈できる。
  4. ARIMA / SARIMA モデルの構造を理解し、次数を決められる。
  5. 予測精度指標（MAE/RMSE/MAPE）を使い分け、ベースラインと比較できる。
  6. 沖縄の需要特性（冷房主体・観光）を分析できる。

前提知識（第8回・第10回との接続）

第8回で見た負荷変動の 2 分類を再掲する。

種別 性質 対応する制御 本回の位置づけ
(1) ゆっくりした大きな変化 予測可能 ELD（経済負荷配分運転） 本回で予測する
(2) 短周期の頻繁な変化 予測困難 LFC 予測しない（制御で吸収）

第10回では供給側（再エネ）を予測した。本回は需要側である。

予測すべき正味需要（ネットロード）=需要−再エネ出力\boxed{\text{予測すべき正味需要（ネットロード）} = \text{需要} - \text{再エネ出力}}予測すべき正味需要（ネットロード）=需要−再エネ出力​

第8回の ELD はこの正味需要に対して発電機の出力配分を決める。

11.2.2 気温と需要の関係 — 非線形性が本質

需要と気温の関係は直線ではなく V 字（または U 字）になる。

 需要
  ↑
  │＼                              ／
  │  ＼      暖房需要      冷房需要／
  │    ＼                      ／
  │      ＼________________／     ← 快適域（空調不要）
  └────┴──────┴──────┴──────→ 気温 [°C]
       10      18     24      35

モデル化の方法:

(1) 度日法（degree-day） — 最も古典的で解釈しやすい

HDD=max⁡(TbaseH−Ta, 0),CDD=max⁡(Ta−TbaseC, 0)\text{HDD} = \max(T_\text{base}^H - T_a,\ 0), \qquad \text{CDD} = \max(T_a - T_\text{base}^C,\ 0)HDD=max(TbaseH​−Ta​, 0),CDD=max(Ta​−TbaseC​, 0)

HDD は暖房度日（Heating Degree Day）、CDD は冷房度日（Cooling Degree Day）。 基準温度は日本では TbaseH=15∼18T_\text{base}^H = 15\sim18TbaseH​=15∼18 °C、TbaseC=22∼24T_\text{base}^C = 22\sim24TbaseC​=22∼24 °C。

y=β0+βH HDD+βC CDD+⋯y = \beta_0 + \beta_H\,\text{HDD} + \beta_C\,\text{CDD} + \cdotsy=β0​+βH​HDD+βC​CDD+⋯

(2) 区分線形（piecewise linear） — 折れ点を複数持たせる

(3) スプライン・多項式 — 滑らかな非線形性を表現

体感温度の考慮: 実際の冷房需要は気温だけでは決まらない。

要因 影響
湿度 高いほど不快指数が上がり冷房需要増（沖縄で重要）
日射量 日射が強いと室温が上がる
風速 風が強いと体感温度が下がる
前日の気温（蓄熱効果） 建物の熱容量により前日の暑さが残る

不快指数（THI）:

THI=0.81Ta+0.01H(0.99Ta−14.3)+46.3\text{THI} = 0.81T_a + 0.01H(0.99T_a - 14.3) + 46.3THI=0.81Ta​+0.01H(0.99Ta​−14.3)+46.3

HHH は相対湿度 [%]。THI > 80 で「暑くてたまらない」とされる。

沖縄で不快指数が効く理由: 那覇の 7〜8 月の平均湿度は 75〜80% と高い。 気温が本土より低くても（那覇の最高気温は東京より低い日が多い）、 湿度が高いため冷房需要が発生する。 気温だけのモデルでは沖縄の需要を説明できない。

蓄熱効果（ラグ項）: 前日・数日前の気温も効く。

Teff(t)=∑k=0KwkTa(t−k),∑wk=1T_\text{eff}(t) = \sum_{k=0}^{K}w_k T_a(t-k), \qquad \sum w_k = 1Teff​(t)=k=0∑K​wk​Ta​(t−k),∑wk​=1

指数減衰の重み wk∝λkw_k \propto \lambda^kwk​∝λk（λ≈0.7\lambda \approx 0.7λ≈0.7）がよく使われる。

図 11.3　需要と気温の関係（左）と、度日の基準温度を変えたときの当てはまり（右）。低温側でも高温側でも需要が増える V 字になり、最適な基準温度は 21.5 °C（R² = 0.407）。

図 11.4　度日の定義（左）と不快指数 THI と需要の関係（右）。V 字を基準温度で折って 2 本の直線にするのが度日。蒸し暑い沖縄では THI との相関 0.701 が気温単独の 0.685 を上回る。

11.2.4 時系列モデル — AR から SARIMA へ

AR（自己回帰）モデル — 過去の値の線形結合

AR(p):yt=c+∑i=1pϕiyt−i+εt\text{AR}(p): \quad y_t = c + \sum_{i=1}^{p}\phi_i y_{t-i} + \varepsilon_tAR(p):yt​=c+i=1∑p​ϕi​yt−i​+εt​

MA（移動平均）モデル — 過去の誤差の線形結合

MA(q):yt=c+εt+∑i=1qθiεt−i\text{MA}(q): \quad y_t = c + \varepsilon_t + \sum_{i=1}^{q}\theta_i\varepsilon_{t-i}MA(q):yt​=c+εt​+i=1∑q​θi​εt−i​

ARMA(p,q) — 両者の組み合わせ。定常時系列に適用できる。

定常性（stationarity）: 平均・分散・自己共分散が時間によらないこと。 電力需要はトレンドと季節性を持つのでそのままでは非定常である。

ARIMA(p,d,q) — ddd 階差分を取って定常化してから ARMA を当てる。

∇dyt=(1−B)dyt,B yt=yt−1 (ラグ演算子)\nabla^d y_t = (1-B)^d y_t, \qquad B\,y_t = y_{t-1}\ (\text{ラグ演算子})∇dyt​=(1−B)dyt​,Byt​=yt−1​ (ラグ演算子)

SARIMA(p,d,q)(P,D,Q)s(p,d,q)(P,D,Q)_s(p,d,q)(P,D,Q)s​ — 季節差分を追加

ΦP(Bs)ϕp(B)(1−B)d(1−Bs)Dyt=ΘQ(Bs)θq(B)εt\Phi_P(B^s)\phi_p(B)(1-B)^d(1-B^s)^D y_t = \Theta_Q(B^s)\theta_q(B)\varepsilon_tΦP​(Bs)ϕp​(B)(1−B)d(1−Bs)Dyt​=ΘQ​(Bs)θq​(B)εt​

電力需要では s=24s = 24s=24（日周期）または s=168s = 168s=168（週周期）を使う。

SARIMAX — 外生変数（気温など）を追加したもの。実務ではこれを使う。

11.2.7 検証の設計 — 時系列で最も間違えやすい点

通常の交差検証（ランダム分割）を使ってはいけない。

未来のデータで学習し過去を予測することになり（データリーク）、 非現実的に良い精度が出てしまう。

正しい方法: 時系列分割（walk-forward validation）

 分割1: [====学習====][検証]
 分割2: [======学習======][検証]
 分割3: [========学習========][検証]
 分割4: [==========学習==========][検証]
                                     → 時間

さらに注意すべき点:

  • 特徴量にも未来の情報を入れない。 例: 「その日の平均気温」は当日が終わらないと分からない。 予測時点で入手可能な情報（気象予報値）だけを使うこと。
  • 予報値で学習するか、実測値で学習するか。 運用時は予報値しか使えないので、予報値で学習するのが正しい。 実測値で学習すると、運用時に精度が落ちる。

図 11.9　検証データの分割の仕方（左）と、その結果（右）。時系列分割では RMSE 41.7 MW だが、ランダム分割では 36.1 MW と 14% 良く見える。隣の時刻が学習に混ざるリークによるもので、運用では出ない性能である。

11.2.8 沖縄の電力需要特性

特性 内容 予測への影響
冷房主体 暖房需要がほぼない。年間の需要ピークは夏 V 字ではなく片側（冷房側）のみのモデルでよい

"""第11回 デモ1: 需要データの生成と時系列分解"""
import numpy as np
import pandas as pd
import matplotlib.pyplot as plt

plt.rcParams['font.family'] = ['Hiragino Sans', 'Yu Gothic', 'DejaVu Sans']
rng = np.random.default_rng(42)

def make_okinawa_demand(start="2024-01-01", periods=24*365*2):
    """沖縄本島系統を模した需要データ（1時間値）を生成"""
    idx = pd.date_range(start, periods=periods, freq="h")
    doy   = idx.dayofyear.values
    hour  = idx.hour.values
    dow   = idx.dayofweek.values

    # 気温（那覇: 年平均23.5度、夏冬の差が小さい）
    T = (23.5 - 6.0*np.cos(2*np.pi*(doy-25)/365)
         - 3.0*np.cos(2*np.pi*(hour-14)/24)
         + rng.normal(0, 1.5, periods))
    # 湿度（夏に高い）
    RH = np.clip(74 + 8*np.sin(2*np.pi*(doy-100)/365)
                 + rng.normal(0, 6, periods), 40, 98)
    # 不快指数
    THI = 0.81*T + 0.01*RH*(0.99*T - 14.3) + 46.3

    base   = 700.0                                    # ベース需要 [MW]
    daily  = 180*np.sin(2*np.pi*(hour-9)/24) + 90*np.sin(4*np.pi*(hour-7)/24)
    weekly = np.where(dow >= 5, -70.0, 0.0)           # 土日は減る
    # 冷房需要（THI に対する非線形。沖縄は暖房ほぼなし）
    cooling = 14.0*np.maximum(THI - 70, 0)**1.25
    heating =  4.0*np.maximum(16 - T, 0)              # わずかな暖房
    trend   = np.linspace(0, 25, periods)
    noise   = rng.normal(0, 22, periods)

    y = base + daily + weekly + cooling + heating + trend + noise
    return pd.DataFrame({"demand": np.maximum(y, 300),
                         "temp": T, "humidity": RH, "thi": THI}, index=idx)

"""第11回 デモ3: 特徴量エンジニアリングと重回帰"""
import numpy as np
import pandas as pd
from sklearn.linear_model import LinearRegression, Ridge
from sklearn.metrics import mean_absolute_error, mean_squared_error

def make_features(df):
    X = pd.DataFrame(index=df.index)
    # 気温の非線形項
    X["cdd"]  = np.maximum(df.temp - 24, 0)
    X["hdd"]  = np.maximum(16 - df.temp, 0)
    X["thi_c"] = np.maximum(df.thi - 70, 0)
    X["temp"] = df.temp
    # 蓄熱効果（前日までの指数加重平均気温）
    X["temp_lag"] = df.temp.shift(24).ewm(alpha=0.3).mean()
    # 周期項（フーリエ）
    h, doy = df.index.hour.values, df.index.dayofyear.values
    for k in (1, 2, 3):
        X[f"sin_h{k}"] = np.sin(2*np.pi*k*h/24)
        X[f"cos_h{k}"] = np.cos(2*np.pi*k*h/24)
    X["sin_y"] = np.sin(2*np.pi*doy/365)
    X["cos_y"] = np.cos(2*np.pi*doy/365)
    # カレンダー
    dow = df.index.dayofweek.values
    for d in range(6):
        X[f"dow_{d}"] = (dow == d).astype(float)
    X["is_weekend"] = (dow >= 5).astype(float)
    # 自己回帰項（予測時点で入手可能なもののみ）
    X["lag_168"] = df.demand.shift(168)      # 前週同曜日同時刻
    X["lag_24"]  = df.demand.shift(24)       # 前日同時刻
    X["trend"] = np.arange(len(df))/len(df)
    return X

X = make_features(df)
y = df.demand
valid = X.notna().all(axis=1)
X, y = X[valid], y[valid]

"""第11回 デモ4: SARIMA による需要予測"""
import numpy as np
import matplotlib.pyplot as plt
from statsmodels.tsa.statespace.sarimax import SARIMAX
from statsmodels.tsa.stattools import adfuller, kpss, acf, pacf
from statsmodels.stats.diagnostic import acorr_ljungbox

plt.rcParams['font.family'] = ['Hiragino Sans', 'Yu Gothic', 'DejaVu Sans']

# 日平均に集約（1時間値でSARIMAは重いため）
s = df.demand.resample("D").mean()
exog = df[["thi", "temp"]].resample("D").mean()

# --- 定常性の検定 ---
print("=== 定常性検定 ===")
adf = adfuller(s.dropna())
print(f"ADF : 統計量={adf[0]:.4f}, p値={adf[1]:.4f} "
      f"→ {'定常' if adf[1] < 0.05 else '非定常'}")
kp = kpss(s.dropna(), regression="c", nlags="auto")
print(f"KPSS: 統計量={kp[0]:.4f}, p値={kp[1]:.4f} "
      f"→ {'非定常' if kp[1] < 0.05 else '定常'}")

# --- ACF / PACF ---
fig, axes = plt.subplots(2, 2, figsize=(13, 7))
for j, (data, title) in enumerate([(s, "原系列"), (s.diff().dropna(), "1階差分")]):
    axes[0, j].stem(range(31), acf(data, nlags=30), markerfmt=" ", basefmt=" ")
    axes[0, j].set_title(f"ACF（{title}）"); axes[0, j].grid(alpha=0.3)
    axes[1, j].stem(range(31), pacf(data, nlags=30), markerfmt=" ", basefmt=" ")
    axes[1, j].set_title(f"PACF（{title}）"); axes[1, j].grid(alpha=0.3)
    for ax in (axes[0, j], axes[1, j]):
        ci = 1.96/np.sqrt(len(data))
        ax.axhline(ci, color="r", ls="--", lw=0.8)
        ax.axhline(-ci, color="r", ls="--", lw=0.8)
plt.tight_layout()
plt.savefig("../図/ch11_acf_pacf.png", dpi=150)

# --- SARIMAX の学習 ---
n_test = 60
tr, te = s[:-n_test], s[-n_test:]
ex_tr, ex_te = exog[:-n_test], exog[-n_test:]

model = SARIMAX(tr, exog=ex_tr, order=(2,1,2), seasonal_order=(1,0,1,7),
                enforce_stationarity=False, enforce_invertibility=False)
res = model.fit(disp=False)
print(f"\nAIC = {res.aic:.2f}, BIC = {res.bic:.2f}")

fc = res.get_forecast(steps=n_test, exog=ex_te)
pred, ci = fc.predicted_mean, fc.conf_int()

rmse = np.sqrt(np.mean((te - pred)**2))
mae  = np.mean(np.abs(te - pred))
print(f"SARIMAX: MAE={mae:.2f}, RMSE={rmse:.2f}")

# 残差診断
lb = acorr_ljungbox(res.resid, lags=[10, 20], return_df=True)
print("\n=== Ljung-Box 検定（残差の自己相関）===")

第10回 例題 10-3 で見たとおり、予測誤差の減少はそのまま予備力の削減になる。 仮に 3σ3\sigma3σ の予備力を持つなら 3×(42.5−28.9)=40.83\times(42.5-28.9) = 40.83×(42.5−28.9)=40.8 MW の削減になる。

(3) 慎重に判断すべきである。 改善は 1−27.8/28.9=3.8%1 - 27.8/28.9 = 3.8\%1−27.8/28.9=3.8% にすぎない。検討すべき点は

観点 内容
統計的有意性 検証期間を変えても再現するか。単なる偶然でないか
解釈性 重回帰は係数の意味が分かるが、複雑なモデルは説明できない
保守性 運用担当者が挙動を理解し、異常時に判断できるか
計算コスト 再学習・推論のコストに見合うか

電力系統は社会インフラであり、説明できないモデルは運用しにくい。 3.8% の改善のために解釈性を失うのは、多くの場合割に合わない。 ただし、その差が安定して再現し、かつ予備力削減の金額が大きければ採用の余地はある。

11.6 まとめ

キーポイント

  • 電力需要はトレンド＋年周期＋週周期＋日内変動＋気温効果＋不規則変動に分解できる。 第8回の分類でいう「予測可能なゆっくりした変化」が本回の対象である。
  • 需要と気温の関係は非線形（V 字・U 字）。度日法（HDD/CDD）、 区分線形、スプラインでモデル化する。
  • 沖縄では湿度が効く。不快指数 THI を使うと気温単独より相関が高い。 暖房需要がほぼないため冷房側のみの片側モデルでよい。
  • 重回帰は解釈性に優れ実用的。特徴量は気象・カレンダー・周期項（フーリエ）・ 自己回帰項（前週同曜日）を組み合わせる。多重共線性は VIF で確認する。
  • SARIMA(X): 差分で定常化し、ACF/PACF で次数を推定、AIC/BIC で選択、 Ljung-Box 検定で残差診断。外生変数（気温）を入れた SARIMAX が実用的。
  • 評価指標: MAE は頑健、RMSE は大きな誤差を強く罰するため電力では重要、 MAPE は規模の違う系統の比較に使う。
  • ベースライン（前週同曜日）との比較が必須。Skill Score が正でなければ価値がない。
  • 時系列の検証はランダム分割してはいけない（データリーク）。 walk-forward validation を使い、予測時点で入手可能な情報だけを特徴量にする。 運用で予報値を使うなら、学習も予報値で行う。

次回への橋渡し

第11回では統計的手法（重回帰・SARIMA）を扱った。 これらは解釈性に優れるが、次のような限界がある。

  • 非線形な相互作用（気温 × 曜日 × 時刻）を手作業で設計する必要がある
  • 説明変数が多いと過学習しやすい
  • 時系列の長期依存を捉えにくい

第12回では機械学習（ランダムフォレスト、XGBoost、LSTM）を導入し、 これらの限界を超える方法を学ぶ。同時に、 解釈性と精度のトレードオフ、そして機械学習を電力系統という 社会インフラに適用する際の注意点を議論する。
